## 3. テストデータ管理

### 3.1 テストデータの種類
1. フィクスチャーデータ
   - 基本的なテストケース用の固定データ
   - `src/__fixtures__/`ディレクトリで管理
   - Git管理対象

2. モックデータ
   - テストケース固有の一時的なデータ
   - テストファイル内で定義
   - テストコンテキストに依存

3. シードデータ
   - テスト用DBの初期データ
   - `prisma/seed/`ディレクトリで管理
   - マイグレーション時に自動投入

### 3.2 データ管理方針
1. データの分離
   - 環境ごとに独立したデータセット
   - 本番データの流用禁止
   - 個人情報の排除

2. バージョン管理
   - テストデータのバージョニング
   - 変更履歴の記録
   - 依存関係の明確化

3. メンテナンス
   - 定期的なデータクリーンアップ
   - 不要データの削除
   - データ整合性の確認

## 4. CI/CD連携

### 4.1 GitHub Actions設定
```yaml
name: Test
on:
  push:
    branches: [main, develop]
  pull_request:
    branches: [main, develop]

jobs:
  test:
    runs-on: ubuntu-latest
    services:
      postgres:
        image: postgres:15
        env:
          POSTGRES_USER: test_user
          POSTGRES_PASSWORD: test_pass
          POSTGRES_DB: test_db
        ports:
          - 5432:5432
        options: >-
          --health-cmd pg_isready
          --health-interval 10s
          --health-timeout 5s
          --health-retries 5

    steps:
      - uses: actions/checkout@v3
      - uses: actions/setup-node@v3
        with:
          node-version: '18'
          cache: 'npm'
      
      - name: Install dependencies
        run: npm ci
      
      - name: Generate Prisma Client
        run: npm run prisma:generate
      
      - name: Run migrations
        run: npm run prisma:migrate
        env:
          DATABASE_URL: postgresql://test_user:test_pass@localhost:5432/test_db
      
      - name: Run tests
        run: npm run test:ci
        env:
          DATABASE_URL: postgresql://test_user:test_pass@localhost:5432/test_db
          NEXTAUTH_SECRET: test_secret
          CLOUDINARY_CLOUD_NAME: test_cloud
          CLOUDINARY_API_KEY: test_key
          CLOUDINARY_API_SECRET: test_secret
      
      - name: Upload coverage
        uses: codecov/codecov-action@v3
```

### 4.2 テスト実行環境
1. 開発環境
   - ローカルマシン
   - 開発用DBを使用
   - 手動実行

2. CI環境
   - GitHub Actions
   - テスト用DBを使用
   - 自動実行

3. ステージング環境
   - 検証サーバー
   - ステージング用DBを使用
   - デプロイ前テスト
