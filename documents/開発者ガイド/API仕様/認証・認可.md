# 認証・認可API仕様

## 概要
Modern TimesウェブサイトのAPIは、NextAuth.jsを使用した認証システムを実装しています。
管理者向けAPIへのアクセスには適切な認証が必要です。

## 認証方式

### 管理者認証
- 認証方式：JWTベース
- 実装：NextAuth.js
- セッション管理：サーバーサイドセッション

### 認証フロー
1. ログインリクエスト
2. 認証情報の検証
3. JWTトークンの生成
4. セッションの確立

## 認可制御

### ロールベースアクセス制御
- 管理者（admin）：全機能にアクセス可能
- 一般ユーザー：公開APIのみアクセス可能

### 保護されたAPIエンドポイント
以下のエンドポイントには管理者認証が必要：
- `/api/products/*`（POST, PUT, DELETE）
- `/api/categories/*`（POST, PUT, DELETE）
- `/api/orders/*`
- `/api/reviews/*`（管理操作）
- `/api/news/*`（POST, PUT, DELETE）

## セキュリティ要件

### トークン
- JWT形式
- 有効期限：24時間
- 暗号化アルゴリズム：HS256

### セッション
- HTTPSのみ
- Secure Cookie使用
- CSRF対策実装

### アクセス制御
- Rate Limiting実装
- IPベースのアクセス制限
- 不正アクセス検知

## 実装例

### APIルートの保護
```typescript
import { getServerSession } from 'next-auth'
import { authOptions } from '@/app/api/auth/[...nextauth]/route'

export async function POST(request: Request) {
  const session = await getServerSession(authOptions)
  
  if (!session || session.user.role !== 'admin') {
    return NextResponse.json(
      { error: 'Unauthorized' },
      { status: 401 }
    )
  }
  
  // 処理を続行
}
```

### ミドルウェアでの認証チェック
```typescript
import { withAuth } from 'next-auth/middleware'

export default withAuth(
  function middleware(req) {
    const token = req.nextauth.token
    const isAdmin = token?.role === 'admin'
    const isAdminRoute = req.nextUrl.pathname.startsWith('/admin')

    if (isAdminRoute && !isAdmin) {
      return NextResponse.redirect(new URL('/admin/login', req.url))
    }
  },
  {
    callbacks: {
      authorized: ({ token }) => !!token
    }
  }
)
```

## セキュリティのベストプラクティス

### パスワード管理
- ハッシュ化：bcryptを使用
- ソルト：自動生成
- 最小長：8文字

### セッション管理
- セッションの定期的な更新
- 不活性セッションの自動終了
- 同時ログインの制限

### アクセス制御
- 最小権限の原則
- アクセスログの記録
- 定期的な監査

## トラブルシューティング

### 認証エラーの対処
1. トークンの有効期限確認
2. 認証情報の再確認
3. セッションのクリア

### 認可エラーの対処
1. ユーザーロールの確認
2. 必要な権限の確認
3. アクセス権限の見直し
