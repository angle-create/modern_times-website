# テスト実施方法

## 概要
Modern Timesウェブサイトでは、Jest と React Testing Library を使用してテストを実施します。
ユニットテスト、統合テスト、E2Eテストを通じて、アプリケーションの品質を確保します。

## テスト環境のセットアップ

### 必要なパッケージ
```bash
npm install --save-dev jest @testing-library/react @testing-library/jest-dom @testing-library/user-event jest-environment-jsdom
```

### テスト設定ファイル
- `jest.config.js`: Jestの基本設定
- `jest.setup.js`: テスト実行前の共通設定

## テストの実行方法

### すべてのテストを実行
```bash
npm test
```

### 監視モードでテストを実行
```bash
npm run test:watch
```

### カバレッジレポートの生成
```bash
npm run test:coverage
```

## テストの種類と実装場所

### 1. コンポーネントテスト
場所: `src/app/**/__tests__/`
- ページコンポーネント
- 共通コンポーネント
- フォームコンポーネント

### 2. APIルートテスト
場所: `src/app/api/**/__tests__/`
- エンドポイントの動作確認
- リクエスト/レスポンスの検証
- エラーハンドリング

### 3. ユーティリティ関数テスト
場所: `src/utils/__tests__/`
- フォーマット関数
- バリデーション関数
- ヘルパー関数

## テストの作成ガイドライン

### 1. コンポーネントテスト
```typescript
import { render, screen } from '@testing-library/react'
import YourComponent from '../your-component'

describe('YourComponent', () => {
  it('期待する動作の説明', () => {
    render(<YourComponent />)
    expect(screen.getByText(/表示されるテキスト/i)).toBeInTheDocument()
  })
})
```

### 2. APIルートテスト
```typescript
import { NextRequest } from 'next/server'
import { GET, POST } from '../route'

describe('API Route', () => {
  it('期待する動作の説明', async () => {
    const request = new NextRequest('http://localhost:3000/api/endpoint')
    const response = await GET(request)
    expect(response.status).toBe(200)
  })
})
```

### 3. ユーティリティ関数テスト
```typescript
import { yourFunction } from '../your-function'

describe('yourFunction', () => {
  it('期待する動作の説明', () => {
    expect(yourFunction('input')).toBe('expected output')
  })
})
```

## モックの使用方法

### 1. APIのモック
```typescript
jest.mock('@/lib/api', () => ({
  getData: jest.fn(() => Promise.resolve(mockData)),
}))
```

### 2. Next.jsの機能のモック
```typescript
jest.mock('next/navigation', () => ({
  useRouter: jest.fn(() => ({
    push: jest.fn(),
  })),
}))
```

### 3. 環境変数のモック
```typescript
beforeAll(() => {
  process.env.NEXT_PUBLIC_API_URL = 'http://localhost:3000/api'
})
```

## テストカバレッジ

### カバレッジ目標
- ステートメントカバレッジ: 80%以上
- ブランチカバレッジ: 80%以上
- 関数カバレッジ: 90%以上
- 行カバレッジ: 80%以上

### カバレッジレポートの確認
1. `npm run test:coverage` を実行
2. `coverage/lcov-report/index.html` を確認

## ベストプラクティス

### 1. テストの構造
- 準備（Arrange）
- 実行（Act）
- 検証（Assert）
の3ステップで記述

### 2. テストケースの命名
- 何をテストするのか
- どのような条件で
- どのような結果を期待するのか
が分かる名前を付ける

### 3. テストの独立性
- 各テストは独立して実行できること
- テスト間で状態を共有しない
- beforeEach でテスト環境をリセット

## トラブルシューティング

### テストが失敗する場合
1. エラーメッセージを確認
2. テストの実行環境を確認
3. モックが正しく設定されているか確認
4. コンポーネントの更新に追従しているか確認

### よくあるエラーと対処法
1. `TypeError: Cannot read property of undefined`
   - モックの設定を確認
   - コンポーネントのpropsを確認

2. `Error: Timeout of 5000ms exceeded`
   - 非同期処理の待機を確認
   - テストタイムアウトの設定を調整

## CI/CDパイプライン

### GitHub Actionsでの自動テスト
```yaml
name: Test
on: [push, pull_request]
jobs:
  test:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v2
      - uses: actions/setup-node@v2
      - run: npm ci
      - run: npm test
```
